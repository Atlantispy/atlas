# Explicit final source construction

This additive entry connects source emission, source planning and explicitly accepted construction to the same selected payload and fresh/prepared profile producer. It preserves the older r2 source API when no construction context is supplied. It does not enable a workload or grant run, Release or scientific acceptance.

Use `build_candidate.py source --repo REPO --out NEW_DIRECTORY --construction-context CONTEXT --context-sha256 SHA256` for the selected source route. `check` and `plan --plan-root NEW_PLAN_DIRECTORY` authenticate the same exact inputs without executing the payload. `apply` also requires `--plan-root`, `--plan-sha256` and the independently reviewed entry hash in `--reviewed-constructor-sha256`. Run with Python `-B`. Output roots must be absent, ordinary and disjoint; existing generations are never overwritten.

The closed external context binds the complete public source map, explicit destination authority, selected membership, original historical inputs, actual parent receipts and the existing paired-profile component. Those original runtime/history dependencies are required inputs and are not supplied or fabricated by this public source tool. Public source bytes and private historical identities remain separate. The DATA gate permits only two fixed byte-identity pairs: the selected public i03 control fixture and the public i04 scientific provenance text. Either or both exact pairs may change; DATA membership and every other DATA byte remain fixed. The i04 text retains the decision date, conditions, replacements, one-sided belt declaration and the order of sizing probes and dependent controls.

Source emission writes the actual constructor payload plus its source manifest. The manifest retains the full construction selection in `files` and separately names the Release selection in `release_files`; only the identity-capture probe is construction-only. This is not a desktop Release manifest. The fold and installed delivery consumers must authenticate actual closure/roles, translated paths, profile/manifest bindings and their qualification evidence before producing an installed or desktop release.

The selected outer bootstrap uses the current fresh runner's `--mode` and profile operands. Its command-only default and existing explicit launch/internal-workload admission gates remain. The historical stage-orchestration `--stage`/reader-overlap/fallback interface is not represented as equivalent. Prepared restart and installed production keep their existing separate entry points. The constructor does not weaken helper/source authentication, runtime identity capture, completion ordering, output absence or finality checks.

The selected membership can bind the public fixture-identity implementation at
`source/src/atlas_tectonics/reuse.py` through this same context and constructor.
The payload authenticates the complete manifest at fixture-context entry and
retains its exact bytes. Every fixture lookup reads and compares the complete
manifest afresh; mutation, truncation and appended data refuse. The immutable
reference is capped at 8 MiB per active context, with comparison reads bounded to
its length plus one byte and blocks of at most 1 MiB. Existing fixture/source,
finder, root, nesting and final cleanup checks remain. The original context-entry
read/stat race is unchanged; only the new lookup comparison has this read bound.

The explicit source route authenticates this payload with the same selected
member map used by `plan` and `apply`. Selecting it changes source, loaded-code,
composition, profile and manifest identities. Preserve preceding generations and
recordings, construct a fresh successor and qualify its actual receiving route.
The older context-free r2 route retains its original source selection. Neither
route gains interval or Release admission from this source addition or the
focused method controls, and no measured performance improvement is claimed.
