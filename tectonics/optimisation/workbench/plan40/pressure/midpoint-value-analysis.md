## Exactness argument

A candidate value object contains only the existing interval value and a three-state constancy tag. Radial objects additionally contain exactly the source's expression tuple. There is no derivative graph or persistent cache.

- A non-singleton value proves `_jet_is_constant` false regardless of derivative components. A singleton created by `_jet_constant`, or the source's explicitly constructed zero-derivative branch tuples, is classified from its actual derivative witness. Original direct linear jets carry the known first derivative and zero second derivative.
- A singleton produced by general arithmetic is **unknown**, not constant. If any constant or zero-equality branch needs that unknown property, the candidate raises its own narrow unsupported sentinel and the caller discards the attempt and runs the original full midpoint evaluator.
- `_jet_add` preserves the two zero-jet shortcuts before the both-constant shortcut. `_jet_scale` preserves q=0 and q=1 before constancy. `_jet_mul`, reciprocal and power use the same original shortcut order. An ordinary value result is outward-rounded at exactly the same operation boundary and precision as the original jet's component zero; constant results use the original exact scalar expression without rounding. `_jet_power` keeps the original multiplication sequence.
- `_same_radial` retains the original constant-first test and exact `_RadialJet.expression` comparison. Equal interval endpoints alone never establish radial identity. Source wrappers attach radial metadata after edge construction; source zero/identity shortcuts retain it; ordinary arithmetic discards it. The prototype follows those exact locations.
- Original source branch logic for radial clipping, max/min, overlap, donor partitions, unresolved order and explicit zero-derivative enclosures is reused unchanged. An unresolved predicate causes fallback before any dependent branch is taken.

By induction through a successful callback, each input value is the original component zero, every queried shortcut has the original answer, each non-shortcut operation rounds that component at the original point, and each expression-identity branch has the original metadata. Therefore every successful candidate final value equals the original midpoint value. A failed attempt returns no result; full fallback supplies the original callback's result or refusal. This covers accidental cancellation into zero/constant values by refusal rather than an unsound symbolic assumption.

The radial chart candidate duplicates the selected exact radius-extrema/value expression and origin refusal, but does not compute `qprime`, `s'` or `s''`. If its square root gives a singleton, its constancy is unknown and it falls back when reciprocal queries it. This is intentionally conservative; proving a broader exact-root class is optional future work, not needed for viability.

## Bounded exactness evidence

Executed with the existing independent maths interpreter. The portable synthetic invocation is `python -B midpoint_value_probe.py --repo REPO --output RESULT.json`. Two noncollinear 3D ray pairs, two polygon shapes, three jet precisions (32, 96, 160 bits), shell bands, positive/negative donor coefficients, no/one/two donor arrangements and multi-band profiles produced 172 midpoint cases. Complete value pairs and fixed flags matched in every case; all 153 successful fast callbacks also matched the full ordered `_jet_is_constant` decision trace. Eighteen cases used full fallback; one origin case retained the same refusal. Extra controls prove identical radial expression succeeds, equal value enclosures with different radial expressions fail identity, and unknown singleton values 0, 1 and 1/3 all refuse classification.

The 172 cases are synthetic exactness/feasibility controls, not a sample of production occurrence rates. Primitive calls below include the abandoned candidate attempt and full re-evaluation for every fallback. These are instrumented deterministic operation counts, not timings, CPU measurements or whole-stage gains.

## Refuted shortcut

Take the source jet with value `(1/3,1/3)`, first derivative `(1,1)` and second derivative `(0,0)`, then scale by 1/3 at precision 96. The source is nonconstant and produces a dyadic enclosure around 1/9. Replacing its derivatives by zeros makes `_jet_is_constant` true and returns exact `(1/9,1/9)`. This changes the retained numerical record despite the apparently better value. The probe asserts this mismatch and asserts the conservative unknown tag refuses it. Similar accidental zeros and identities must never be inferred from midpoint value alone.

## Rollout resource and lifetime contract

The prototype now isolates the candidate in `attempt_value`. It handles only `UnknownConstant`, leaves the exception handler, returns `(False, None)` and only then lets the caller invoke the original callback. Calling the original from inside an `except` block would retain the candidate's traceback and temporaries during fallback; the isolated helper avoids that overlap. A deliberate lifetime-marker fault control confirms the failed candidate frame's local object is released before the caller receives the unsupported return on the tested interpreter. This is a Python control-flow check, not validation of the real budget ledger.

The later implementation should keep the original `V._work((left,right,denominator,*values), budget)` live throughout full-interval evaluation, candidate attempt, optional original midpoint fallback and tight-bound construction. It must not replace that admission with a smaller estimate because fewer operations are intended. Candidate objects are invocation-scoped value/tag records with no child references, derivative closures, memo table or cross-call owner; radial metadata retains only the existing bounded expression shape. A successful attempt returns the three plain value pairs; candidate wrappers then die. An unsupported attempt returns no values or exception object, and all candidate scratch must be released before original fallback.

Before integrating, prove a maximum simultaneous object/payload envelope for the actual callback's locals and expression tags at the admitted coefficient widths. Compare it with the existing operation reservation; retain that reservation unchanged if it already covers the candidate. If a separate transient charge is necessary, use an explicitly optional reservation whose refusal cleanly declines the candidate and releases any partial scratch before the original callback. A new mandatory budget refusal would violate the fallback contract. Do not catch generic numerical/resource/cancellation exceptions as an optimisation miss. Allocation/lease cleanup must execute on both the unsupported sentinel and every other exception while preserving the latter's original propagation.

Required focused integration controls are: actual ledger refusal before any candidate allocation; optional scratch refusal with identical original result; unknown-constancy fallback with no live candidate scratch; an injected candidate arithmetic error propagated rather than swallowed; cancellation with no leaked lease; same outward rounds/source branch/metadata/certificate and complete output/leaf parity. These remain later implementation obligations. The current no-op partition/admission fixtures and arithmetic replays establish none of them.
