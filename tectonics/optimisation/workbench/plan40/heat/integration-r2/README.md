# Heat arithmetic receiving integration

WORKING NON-CANON. This is the successor combined source selection for the
optimisation branch. It connects the accepted C3 and C8 implementations to the
existing exact-arithmetic heat consumers. C13 remains excluded after its measured
regression. This does not replace the different NumPy/SciPy heat algorithms in
the main package or migrate a historical checkpoint.

## Connected consumers

| Implementation | Actual receiving connections |
| --- | --- |
| C3 signed-zero dot | Certificate r1 and native dot → certification inventory → full certificate r3 and functional bounds. The parallel observer's outer and embedded export sets include all eighteen MPFR functions; its embedded certificate/native pins identify C3. |
| C8 exact owner-unit scale | Assembler → inventory → owning assessment → forward r13 and stage lifetime r3. Both receivers use the same owner and result classes, including refinement, cancellation and transfer/close handling. |
| Source and recovery binding | The existing issuer dynamically captures the selected closure. Explicit successor pins then connect checkpoint consumer, joined consumer, restored binding, RAM context and RAM recovery. Earlier-generation identities remain refused. |

Public binding repairs resolve the actual imported Decimal policy, spatial
transport and heat modules. Their exact pins, runtime constraints, numerical
functions, accounting formulas and source checks remain in force. The worker
observer resolves only the library belonging to the loaded `gmpy2` installation,
with an unambiguous package identity and the existing exact DLL pin. It does not
search arbitrary machine paths or accept a different library.

## Use the selected source layout

[SOURCE-MAP.json](SOURCE-MAP.json) binds each member to an existing public file.
Unchanged files are referenced, not duplicated in Git. The parent
[Plans19–20 map](../../../plans19-20/SOURCE-MAP.json), accepted arithmetic sources
and historical receipts remain unchanged.

From the repository root, construct a **new** destination:

```text
python -B tectonics/optimisation/workbench/plan40/heat/integration-r2/build_selection.py --repo . --output ../atlas-heat-source
```

The output contains `helpers`, `src` and `SOURCE-MANIFEST.json`. Use those two
import roots together in a fresh process when using this selected heat route;
mixing old and new helper imports is not supported. Existing forward, issuer
and recovery module names select the new receiving graph in that layout.
The existing `private_heat_joined_consumer_r6.forward(...)` entry calls the issuer
and forward kernel, which now reach both selected arithmetic implementations.
Its owner, mesh, execution context, boundary and store contracts remain unchanged.
Construction refuses source drift, incomplete membership and an existing
destination. It neither opens a checkpoint nor launches an interval or worker.

The `--write-map` and `propagate_bindings.py` commands are source-authoring tools,
not a way to repair a failed historical receipt. They verify the fixed predecessor
and declared pin locations; any new selection requires its own reviewed identity.

## Focused verification and limits

`test_build_selection.py` and `test_propagate_bindings.py` check construction,
source membership, dependent pins and fail-closed controls using the standard
library. The following checks require the compatible Atlas scientific
environment and a new materialised source tree:

- `check_c3_binding.py --source-tree TREE`: full certificate assessment and
  functional bounds, unchanged accounting/runtime constraints, source faults,
  complete embedded observer export sets and library-location controls.
- `check_c8_forward_binding.py --repo REPO --source-tree TREE --output NEW.json`:
  actual forward receiver and lifetime transfer, refinement projection,
  cancellation and budget refusal, with exact source checks before and after.
- `check_receiving_chain.py --source-tree TREE --output NEW.json`: actual issuer,
  checkpoint, joined and restored-source checks through the selected graph,
  including refusal controls. It does not restore a historical store.

These small checks do not launch workers or full intervals. Worker execution,
historical checkpoint migration, private runtime admission, the final package
landing and scientific acceptance retain their separate contracts and holds.
Full forward numerical execution is not established by an import or source check.
Materialisation does not make the fresh/prepared full-interval drivers independently
runnable: those harnesses still require their separately controlled private inputs.

The arithmetic remains the [measured implementation](../implementation-r1/MEASUREMENTS.md):
C3 has mixed fixture performance, C8's owning-receiver fixture saved 1.339%, and
C13 regressed 6.001%. Those retained component measurements are not a new timing
of this integrated generation and do not establish an Atlas-wide speed-up.
