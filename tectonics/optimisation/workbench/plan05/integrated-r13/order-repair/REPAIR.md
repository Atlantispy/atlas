# Physical scratch ordering contract

The additive repair targets the authenticated cell permutation whose unchanged
LOW/HIGH finite arithmetic previously produced different exact accounts.
The original native layouts remain unchanged. Current outcome and source
identities are in `../../README.md` and `../../SOURCE-MAP.json`.

`prepare` derives keys from actual indexed collar/exterior physical support:
voxel/index, radial layer, cone, source component and physical grid annotations.
Duplicate keys and unsupported support families refuse. Keys never use energy,
temperature, residual, nearest centroid or provenance-dependent thermal IDs.
Both LOW and HIGH, including H5a's shared preparation, use that physical scratch
cell order. Before FINISH, an owned view restores the caller cell axis and
original face-owner order. The projected predictor leaves are precisely
`energy`, `absolute_target_decimal` and `raw_outward_energy_decimal`.

The demonstrated repair covers the selected cell permutation with the same
physical face order/orientation. Arbitrary face permutations and
differential-support geometry are not qualified. Equations, tolerances,
precision ladder, original input bytes and output-row contracts are preserved.

A native WorkBudget workspace admits added containers before allocation.
Concrete operation custody is registered before row/map creation. Startup
owners remain live while scratch views borrow their leaves; complete predictor
owners remain charged while inverse views borrow theirs. This is logical
accounting, not a heap or RSS claim.

On failure, the registered operation retains admitted workspace, producer
references, completed native wrappers, exact primary exception and suspended
traceback. A fixed emergency slot retains admission if owner construction or
registration fails, blocking another operation until release. Independently
extracted aliases remain funded even if a caller discards its own exception.

`retained_failures()` exposes concrete owner IDs. Release requires
`release_failure(id, acknowledge_no_borrows=True)` after all extracted aliases
and traceback borrows have ended. The caller must not first clear owner-held
frames or close borrowed producers. Release clears suspended frames while
funded, then closes the workspace. Native outer owners have their own lifetime
if the caller still retains the primary exception. Exception death and negative
scans do not authorise release.

The guarded builders require exact original forward/issuer bytes and refuse
overwrite. Both arm-specific overlays are retained. Forward source discovery
includes the ordering helper and original native graph; issuer loaded-function
identity includes its operation methods. No source-identity rule is relaxed.

Retained tests cover original order sensitivity and exact repair, actual native
mesh ownership, inverse mapping, duplicate/incidence/admission refusals,
cancellation, partial native allocations, registration failure and escaped
aliases, plus a manufactured eight-cell full LOW/HIGH/FINISH seam. Eleven
controls passed separately for each native layout. Those fixtures are distinct
from the authentic six-worker pair and confer no scientific acceptance.
