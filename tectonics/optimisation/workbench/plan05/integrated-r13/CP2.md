# Exact correspondence contract

This public contract describes `verify_d02_r13.py`. Original document and export
identities are in `../SOURCE-MAP.json`; current results are in `../README.md`.
The verifier operates on saved evidence without importing the native science
graph.

Completion, companion hashes, five binary64 shapes/raw/file bindings, native
result/caller/control identities, owner-release receipts and exact source
bindings are checked before attribution. The required six-file source subset
and named supplemental files are checked; this is not a claim of complete
dependency-graph proof.

Native physical support preimages provide a single complete unique cell map
for every input, array and cell account. Faces use a separate exact polygon,
owner, incidence and orientation map. Exact grid coordinates are reconstructed
from bound integer/rational pools; storage indices alone do not prove equality.
Counts come from each capture. Values are never sorted to manufacture a map;
there is no nearest-neighbour match, tolerance or unnamed metadata exception.

Physical context, transported stocks and three input arrays must agree before
solver attribution. The five arrays compare bitwise. Four cell-account
families, signed paired-face energies and scalar accounts compare exactly.
Within-arm energy balances, residual identities, source/boundary totals and
the supplied residual target are checked with rational arithmetic.

Every metadata leaf has a disposition. Named native identities and numeric
resource observations retain their own meanings; numerical policy, execution
mode and physical origin fields remain invariants. Opaque identity differences
do not establish equivalent preimages or a path-only cause. Two ABI-independent
codec components are reconstructed from all saved exact account widths,
including zero and sign reservation. Conversion-work accounting additionally
depends on uncaptured Python object-size constants; the verifier does not
substitute its own ABI. Missing required authority remains unresolved.

Historical linkage is independent of the new-run comparison. Every saved
array and exact metadata byte binding must match its historical counterpart.
Array inventories compare validated names/shapes semantically, with raw JSON
formatting retained as a diagnostic. Any array or metadata disagreement remains
`NOT_REPRODUCED`, including after another new-run refusal. No historical map
is inferred and no historical file or verifier report is overwritten.

The optional physical-order selection binds exactly the common helper and the
selected arm's forward/issuer overlays. The consumer contract additionally
requires actual proof, dispositions, process/log finality, explicit correctness
acceptance and separate run authority. No successful comparison supplies those
decisions or releases q22.
