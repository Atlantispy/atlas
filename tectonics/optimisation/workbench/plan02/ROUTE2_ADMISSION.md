# Prepared-restart admission

WORKING NON-CANON. This candidate adds by-need admission to the prepared producer,
its external monitored launcher, and its independent reader. It changes no
scientific method, runtime source identity rule or in-run resource limit.

Before creating a run directory, each launcher constructs a command key from the
pinned profile, selected source manifest, operation and modes, entry-point bytes,
Python executable bytes and declared launch environment. Only the producer's
fresh output-directory field is removed from the profile key. A reader retains
the producer output/profile and receipt pin; its own destination is not an input.
The completed-query directory, quotas, storage configuration, preparation and
runtime policy stay bound. Staged/full producers and reader mode/store routes
are separate workloads. Executable identity is not a complete inventory of
installed dependencies; the existing runtime-policy/source verification remains
required and no cross-environment equivalence is inferred.

The repeatable `--peak-record` names a prospective successful LM postcheck or
reader final record containing `atlas.private.route2-peak.r1` evidence. Historical
unbound completion records are refused. The completion writer binds the actual
parsed profile, workload, final guard and control bytes; a producer also binds
launch and tracking records. It checks those bytes remain unchanged before
publishing. Failed completion does not publish eligible evidence. The consumer
rechecks the complete role set, hashes, command key, successful mode/status,
guard/control/process identities, unchanged limits and complete LM checklist or
reader finalisation. Its peak is the final guard's positive integer
`sampled_peak_bytes.process_tree_rss`; the earlier workload mirror may be smaller,
but cannot exceed it. Named malformed, mismatched, changed or duplicate evidence
refuses instead of being skipped.

Producer evidence must also agree on the profile's attempt directory, sibling
launch/tracking paths and the postcheck's output. Parent and workload decisions
must be identical except for their own available-memory and seed observations.

Completion status intentionally depends on evidence capture: that path also
validates admission and guard integrity. Reader finalisation failure writes
FAILED with independent_process_reopen false and no gate_evidence; LM postcheck
failure writes FAILED without gate_evidence. Reader --finalise must use the same
pinned Python executable and reader entry as --launch. LM postcheck instead
derives the workload key from the recorded launch Python; it does not equate that
identity with its own current interpreter. Profile, entry and source identities
must still match at both completion boundaries.

Final records, successful or failed, are exclusive and immutable. A corrected
invocation cannot overwrite or re-finalise a failed reader directory. Recovery
requires a fresh authorised reader attempt in a new output directory against the
unchanged producer checkpoint; LM recovery likewise follows a fresh authorised
producer attempt/profile destination. Preserve the failed record and original
evidence. A named failed record refuses measured-peak qualification without
falling back to a booking. A new attempt without named measurements may use an
explicit booking under the normal rules. Neither recovery path releases a hold
or establishes scientific acceptance.

The largest qualifying measured peak wins. Without measurements, both
`--booking-bytes` and `--booking-basis` are required. No default is invented and a
booking cannot override observations. The unchanged start_gate core computes
`P + ceil(P / 5) + 2 GiB` using integer arithmetic. The parent admits before run
output creation and appends the encoded decision last in the guarded child argv.
The child checks seed zero, arithmetic and its current free memory before its
receipt/native work, and again at the core entry after source selection. This is
not authentication of the prediction: a coherent understated direct child
decision can pass, as in Route 1. The 12-GiB tree RSS, 1-GiB free floor and 16-GiB
logical guards remain the runtime protections. No `-I`/`-E` is added to those
children.

Both admission helpers must be beside the selected runner and bound in its
source manifest. New manifest/profile identities are required; existing receipts
are never repinned. Older Route 1 callers reference START_BYTES; they must be
replaced by the accepted Route 1 chain in the same integration generation.
A Route 2-only swap is not compatible with those old callers. This snapshot
contains the selected compatible generation; the corresponding private live
integration and scoped C18 checks are recorded separately. It does not create
the later final assembly, authorise N9 replay or release any hold.

Before native use, the selected generation must pass a fresh-child source
closure check with the unchanged probe beside its selected runner and both gate
helpers, within the real workspace/interpreter boundary. Independently enumerate
and pin the expected imported sources; do not preserve an obsolete count of four.
The minimal synthetic probe fixture now needs six files (probe, runner, both gate
helpers and two synthetic native-package files). This checks loaded-module
closure separately from RestartSources verification and involves no scientific
solve or store publication. The omitted probe in isolated W staging would launch
the original runner and cannot establish this integration boundary.

The checks use synthetic files and commands, exercise refusal/no-output and
completion evidence corruption, and preserve the existing focused caller tests.
Their actual results belong in the Plan 02 owner record after execution; no
scientific interval or performance result is claimed by this document.
