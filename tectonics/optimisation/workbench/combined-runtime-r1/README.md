# Combined endpoint and capture source selection

This selection combines endpoint lookahead and compact support retention with
bounded exact-byte diagnostic captures. It also retains the selected geometry,
pressure and heat implementations used by their existing consumers.

The completed source snapshot contains 645 members: 240 native sources and 405
helpers. It supplies 22 changed copies and references 623 existing public files.
Its source map SHA-256 is
`93ddf7a0fdc2c58d4f45e73d6f2615d37879411bc443534582c10f5d8c4ea2c2`.
The qualified helper fold and installed-package delivery remain outstanding;
this source layout is not an installed application update or runtime admission.

`SOURCE-MAP.json` names every selected member and its exact public bytes. Most
members refer to existing published sources; only changed members are copied
here. Earlier source maps remain historical records. Public source identities
do not authenticate measurements made on private predecessors.

To construct a separate source layout, run from the repository root:

```text
python -B tectonics/optimisation/workbench/combined-runtime-r1/build_selection.py --repo . --output NEW_DIRECTORY
```

The builder verifies the complete selection before writing and refuses existing
outputs, changed sources and linked destination paths. It imports no scientific
module. The resulting `src` and `helpers` directories form one selection and
must be used together. Building this layout grants no execution authority.

The shared retained scope keeps its fixed 256 MiB budget and gives each verified
partition an additional allowance for three 2,112 B ownership carriers per
support. Identical partition facades share that allowance; different live
partitions have separate allowances. A fourth retained carrier for a support
refuses. Transient reads and exports remain in the fixed budget, and all charges
remain subject to the whole-run and machine guards.

Large canonical capture items acquire a reservation before serialisation and
retain it with their bytes until consumption or release. Separate key and
punctuation yields preserve ownership without changing the logical stream.

Runner and worker-bootstrap fixes authenticate the selected source/package roots
and checked loaded-module objects, rejecting foreign or replaced modules while
preserving legitimate mutable runtime state. Prepared capture setup is connected
to the actual driver entry and refuses missing or wrong backends before subsequent
work.

Focused evidence includes 59 lifecycle tests and 99 fake-session lookahead checks
on the earlier receiving source, 11 runner/bootstrap seam tests and six public
materialiser checks. A final-source prepared-entry fixture covers six subcases
with inert dependencies and stops immediately after the capture gate. It proves
entry wiring and refusal order, not native authentication or full prepared
execution. Earlier component and q18 evidence retain their original scope.
